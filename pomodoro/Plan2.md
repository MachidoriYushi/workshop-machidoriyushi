# Feature 起点の実装計画

## 目的

このドキュメントは、`features.md` に記載された各 Feature について、現在の実装状況、足りていないところ、今後の実装計画を整理する。

既存の `plan.md` は工程別の計画だが、この `Plan2.md` では Feature ごとに「仕様に対して何ができていて、何が不足していて、次に何を実装するか」を追える形にする。

## 現在の前提

- Go の `net/http` で HTML と静的ファイルを配信している。
- タイマーの主要ロジックは TypeScript の `web/static/ts/timer.ts` に実装している。
- ブラウザ配信用の `web/static/js/timer.js` は `tsc` による生成物である。
- JavaScript テストは生成後の `timer.js` に対して実行している。
- 統計と設定は `localStorage` 相当のストレージに保存する設計である。
- 現在のUIには、作業/休憩の手動切り替え、作業時間/休憩時間の設定変更UIはない。

## Feature 1: 作業タイマー

### 現状

- 初期状態は `mode = work`、`status = idle`、`durationSeconds = 1500` で作成される。
- 画面初期表示は `25:00` と `作業中` になる。
- 作業完了時に `completedWorkSessions` と `totalFocusSeconds` が更新される。
- 作業完了後の `nextMode` は `break` になる。

### 足りていないところ

- 作業時間をユーザーが変更するUIがない。
- 作業時間を変更した場合に、現在の `durationSeconds` と `remainingSeconds` へ反映する仕様が未実装である。
- 作業完了後に休憩へ移ることは内部的に行っているが、ユーザーに「次は休憩」という状態が明確に表示されていない。

### 実装計画

1. 作業時間設定UIを追加するか、初期版では固定25分と明記する。
2. 設定UIを追加する場合は、`workDurationSeconds` の変更テストを先に追加する。
3. 作業完了後の画面内メッセージに「休憩を開始できます」を表示する。

### 検証

- 初期状態テスト。
- 作業完了時の統計更新テスト。
- 作業完了後の次モードテスト。
- ブラウザで作業完了後の表示確認。

## Feature 2: 休憩タイマー

### 現状

- `mode = break` の状態はロジック上扱える。
- 休憩完了時に `completedBreakSessions` と `totalBreakSeconds` が更新される。
- 休憩完了後の `nextMode` は `work` になる。

### 足りていないところ

- 初期UIから手動で休憩タイマーへ切り替える手段がない。
- 作業完了後に休憩タイマーへ自動準備されるが、明示的なモード切り替えUIはない。
- 休憩時間をユーザーが変更するUIがない。

### 実装計画

1. 作業完了後の自動準備を正式仕様として採用するか、手動切り替えボタンを追加するか決める。
2. 手動切り替えを採用する場合は、`SWITCH_TO_BREAK` と `SWITCH_TO_WORK` のテストを追加する。
3. 休憩時間設定UIを追加する場合は、`breakDurationSeconds` の変更テストを追加する。

### 検証

- 休憩完了時の統計更新テスト。
- 休憩完了後の次モードテスト。
- UIから休憩タイマーを開始できることの確認。

## Feature 3: タイマー開始

### 現状

- `START` イベントで `idle` または `paused` から `running` へ遷移する。
- `startedAt` と `lastTickAt` が設定される。
- 画面の開始ボタンから開始できる。
- 開始後はボタン表示が `停止` になる。

### 足りていないところ

- ボタン文言が `停止` になっているが、実際の挙動は一時停止である。
- 仕様上の「停止」と「一時停止」の言葉がUIと一致していない。
- 開始時に通知やサウンド再生の事前準備を行う仕様はまだない。

### 実装計画

1. UI文言を `一時停止` に変更する。
2. テスト名と仕様上の用語も「停止」ではなく「一時停止」に寄せる。
3. サウンド通知のブラウザ制限に備え、初回ユーザー操作時の音声初期化が必要か検討する。

### 検証

- `START` の状態遷移テスト。
- ボタン文言のDOM確認。
- 実ブラウザで開始操作を確認。

## Feature 4: タイマー一時停止

### 現状

- `PAUSE` イベントで `running` から `paused` へ遷移する。
- `pausedAt` を記録する。
- `lastTickAt` を `null` にして更新処理を止める。
- UIの `停止` ボタン押下で一時停止する。

### 足りていないところ

- 一時停止前に経過済み時間を即時反映してから止める処理が弱い。
- 現状は直近の `TICK` で更新済みの `remainingSeconds` を保持する設計で、クリック瞬間までの端数は反映しない。
- UI文言が一時停止の意味として明確ではない。

### 実装計画

1. `PAUSE` 時に `now` と `lastTickAt` の差分を反映するテストを追加する。
2. `PAUSE` 実装で停止直前の残り時間を再計算する。
3. ボタン文言を `一時停止`、再開時を `再開` にする。

### 検証

- `PAUSE` の時間反映テスト。
- 一時停止中に時間が減らないことのテスト。
- ブラウザで一時停止/再開の表示確認。

## Feature 5: タイマー再開

### 現状

- `RESUME` イベントで `paused` から `running` へ遷移する。
- `startedAt` と `lastTickAt` を再設定する。
- UIでは一時停止後に同じ開始ボタンから再開できる。

### 足りていないところ

- 再開時のボタン文言が `開始` のままで、状態が分かりにくい。
- 再開後の経過時間計算は `lastTickAt` ベースで動くが、仕様書では `lastTickAt` の意味が説明されていない。

### 実装計画

1. `paused` 状態ではボタン文言を `再開` にする。
2. `features.md` の状態モデルに `lastTickAt` を追記する。
3. 再開後に残り時間が一時停止時点から継続するテストを追加する。

### 検証

- `RESUME` の状態遷移テスト。
- 一時停止から再開した後の `TICK` テスト。
- UI文言の確認。

## Feature 6: タイマーリセット

### 現状

- `RESET` イベントで `idle` に戻る。
- `remainingSeconds` は `durationSeconds` に戻る。
- 時刻情報と `nextMode` はクリアされる。
- UIのリセットボタンから実行できる。
- 初期状態ではリセットボタンが無効になる。

### 足りていないところ

- `completed` 後はすぐ `prepareNextSession` で次セッションへ移るため、完了状態からリセットするUI上の余地がほぼない。
- リセット時に画面内通知メッセージを消すかどうかが未定義である。

### 実装計画

1. 完了後に即次セッションへ移る仕様を採用するなら、`completed` からのリセット仕様を簡略化する。
2. リセット時に通知メッセージをクリアする。
3. リセット時に統計が増えないテストを維持する。

### 検証

- `RESET` の状態遷移テスト。
- リセット時に統計が変わらないことのテスト。
- リセット後の表示確認。

## Feature 7: タイマー完了

### 現状

- `COMPLETE` イベントで `completed` へ遷移する。
- `remainingSeconds` は 0 になる。
- `completedAt` が設定される。
- `nextMode` が設定される。
- UI側の `commit` で統計更新、通知、サウンド、次セッション準備が行われる。

### 足りていないところ

- `completed` 状態をUI上に表示する時間がほぼない。
- 完了メッセージは通知欄に出るが、次セッション準備との関係が分かりにくい。
- 完了後に自動開始するか、手動開始するかの仕様は明確化できていない。

### 実装計画

1. 完了後は「次の休憩を開始できます」のようなメッセージを表示する。
2. 自動開始はしない方針を明記する。
3. 完了後の `prepareNextSession` のテストを追加する。

### 検証

- `COMPLETE` の状態遷移テスト。
- 二重完了防止テスト。
- 完了後のUIメッセージ確認。

## Feature 8: モード切り替え

### 現状

- 完了後に `nextMode` を使って次モードを準備する。
- 作業完了後は休憩、休憩完了後は作業へ進む。

### 足りていないところ

- 手動で作業/休憩を切り替えるUIがない。
- `SWITCH_MODE` イベントは仕様にあるが、実装上は存在しない。
- `paused` 中の手動切り替え確認ダイアログは未実装である。

### 実装計画

1. 初期版では手動切り替えを対象外にするか、モード切り替えボタンを追加するか決める。
2. 追加する場合は `SWITCH_MODE` イベントを `TimerEventType` に追加する。
3. `running` 中は禁止、`paused` 中は確認後リセット相当、というテストを追加する。

### 検証

- 作業/休憩の自動準備テスト。
- 手動切り替えを実装する場合は状態遷移テスト。
- UI操作確認。

## Feature 9: 進捗表示

### 現状

- `calculateProgressPercent` で進捗率を計算している。
- 進捗率は 0 から 100 の範囲に収まる。
- CSS の `conic-gradient` と `--progress` で円形進捗を表示している。
- `TICK` により画面上の残り時間と進捗が更新される。

### 足りていないところ

- `TICK` は `lastTickAt` ベースだが、`calculateRemainingSeconds` は `startedAt` ベースで、計算モデルが2種類ある。
- 長時間タブを非アクティブにした場合の実ブラウザ検証はまだない。
- `formatTime` のテストがない。

### 実装計画

1. タイマー計算を `lastTickAt` ベースで統一するか、`startedAt` ベースへ寄せるか決める。
2. `formatTime` のテストを追加する。
3. タブ復帰時や大きな `TICK` 差分のテストを追加する。

### 検証

- 進捗率計算テスト。
- 大きな経過時間で `completed` になるテスト。
- ブラウザで進捗リング更新を確認。

## Feature 10: 統計表示

### 現状

- `StatsState` を持っている。
- 作業完了時に今日の完了数と今日の集中時間を増やす。
- 休憩完了時に休憩統計を増やす。
- `localStorage` に統計を保存し、初期化時に復元する。
- UIには今日の完了数と今日の集中時間が表示される。

### 足りていないところ

- 日付が変わったときに今日の統計をリセットする処理がない。
- `completedBreakSessions` と `totalBreakSeconds` は保存されるが、UIには表示していない。
- 統計リセット機能がない。

### 実装計画

1. `statsDate` を `StatsState` に追加する。
2. 起動時に保存済み統計の日付を確認し、今日分だけリセットする。
3. 必要なら休憩回数や累計集中時間をUIに追加する。
4. 統計リセットボタンを追加するか検討する。

### 検証

- 日付変更時の今日統計リセットテスト。
- 統計復元テスト。
- UI表示確認。

## Feature 11: ブラウザ通知

### 現状

- `notifyCompletion` で通知送信、フォールバック、スキップ、失敗を扱える。
- 通知許可ボタンがある。
- `Notification.permission` が `default` の場合に許可要求する。
- 完了時に権限があれば通知を送る。

### 足りていないところ

- `Notification.permission` の現在値をUIに常時表示していない。
- 通知失敗時のメッセージが `failed` と `fallback` で十分に分かれていない。
- 通知許可が `denied` の場合の説明文が弱い。

### 実装計画

1. 通知状態表示を追加する。
2. `sent`、`fallback`、`failed` ごとにメッセージを分ける。
3. `denied` の場合はブラウザ設定で変更が必要であることを表示する。

### 検証

- `notifyCompletion` の分岐テスト。
- 通知許可ボタンの手動確認。
- 権限拒否時の表示確認。

## Feature 12: サウンド通知

### 現状

- `playCompletionSound` で再生、無効、スキップ、失敗を扱える。
- Web Audio API で完了音を生成している。
- サウンド有効/無効のチェックボックスがある。
- サウンド設定は保存される。

### 足りていないところ

- ブラウザの自動再生制限により、完了時に初回再生が失敗する可能性がある。
- サウンドテスト再生ボタンがない。
- サウンド再生失敗時の画面表示が弱い。

### 実装計画

1. サウンドテストボタンを追加する。
2. 初回ユーザー操作時にAudioContextを準備する。
3. 再生失敗時に画面内メッセージを出す。

### 検証

- `playCompletionSound` の分岐テスト。
- サウンド設定保存テスト。
- ブラウザでサウンド再生確認。

## Feature 13: レスポンシブ Web UI

### 現状

- `viewport` が設定されている。
- `@media (max-width: 480px)` がある。
- `overflow-x: hidden` を設定している。
- ボタンは `min-height: 52px` でタッチ操作しやすい。
- CSS静的テストがある。

### 足りていないところ

- 実際のブラウザ幅でのスクリーンショット確認は未実施である。
- モックとの見た目の一致度は静的テストだけでは保証できない。
- カード内の縦方向の収まりは端末高さによっては再確認が必要である。

### 実装計画

1. Playwright などを入れるか、手動確認で済ませるか決める。
2. 少なくとも 375px 幅と 1280px 幅で表示確認する。
3. 文字はみ出しや要素重なりがあればCSSを調整する。

### 検証

- CSS静的テスト。
- ブラウザ手動確認。
- 必要に応じてスクリーンショットテスト。

## Feature 14: 設定保存

### 現状

- `STORAGE_KEYS.settings` は `pomodoro.settings` である。
- `STORAGE_KEYS.stats` は `pomodoro.stats` である。
- `saveSettings`、`loadSettings`、`saveStats`、`loadStats` を実装済み。
- 不正JSONや不正な型は既定値へフォールバックする。
- `storage === null` でも落ちない。

### 足りていないところ

- UIから変更できる設定は `soundEnabled` のみである。
- 作業時間と休憩時間の設定UIがない。
- 設定変更時に実行中タイマーへどう反映するかが未定義である。

### 実装計画

1. 初期版では時間設定を固定にするか、設定UIを追加するか決める。
2. 設定UIを追加する場合は、`idle` のときだけ変更可能にする。
3. 実行中に設定変更する場合は、次セッションから反映する仕様にする。

### 検証

- 設定保存/復元テスト。
- 不正値フォールバックテスト。
- UIから設定変更した後の再読み込み確認。

## Feature 15: 画面タイトル更新

### 現状

- `running` 中は `mm:ss - 作業中` または `mm:ss - 休憩中` に更新する。
- `running` 以外では `ポモドーロタイマー` に戻す。

### 足りていないところ

- `paused` 中に一時停止中であることをタイトルに表示していない。
- タイトル更新のテストがない。

### 実装計画

1. `paused` 中は `一時停止 - 12:34` のように表示する。
2. `render` のタイトル更新をテストしやすい関数へ分離する。
3. タイトル文字列生成テストを追加する。

### 検証

- タイトル文字列生成テスト。
- ブラウザで実際のタブタイトル確認。

## 横断的に足りていないところ

### ドキュメントの更新

- `architecture.md` と `plan.md` は JavaScript 前提の記述が残っている。
- 実装本体は `timer.ts`、配信用生成物は `timer.js` であることを明記する必要がある。
- `features.md` に `lastTickAt`、`nextMode`、通知結果、サウンド結果、保存キーを追記する必要がある。

### テストの整理

- 現在は `timer.test.js` に多くのテストが集まっている。
- Feature ごとに見通しを良くするなら、将来的にテストファイルを分割する。
  - `timer-state.test.js`
  - `timer-progress.test.js`
  - `timer-stats.test.js`
  - `timer-storage.test.js`
  - `timer-notification.test.js`

### Go サーバーの整理

- `templatePath` と `staticDir` は実行ディレクトリ差を吸収しているが、やや実装都合が強い。
- ワークショップ用途なら現状でもよい。
- 整えるなら `go run .` は `pomodoro/` で実行する前提にして固定パスへ寄せる。

## 優先順位

### 優先度 A: 仕様とUIのズレを直す

1. 開始ボタンの文言を状態別にする。
   - `idle`: 開始
   - `running`: 一時停止
   - `paused`: 再開
2. 完了後のメッセージを明確にする。
3. `features.md` と `architecture.md` を TypeScript 構成に更新する。

### 優先度 B: 実装仕様を安定させる

1. `lastTickAt` と `TICK` の仕様を明文化する。
2. `prepareNextSession` のテストを追加する。
3. タイトル文字列生成を関数化してテストする。

### 優先度 C: ユーザー操作を増やす

1. 手動モード切り替えを追加するか決める。
2. 作業時間/休憩時間の設定UIを追加するか決める。
3. 統計リセットを追加するか決める。

### 優先度 D: 確認の質を上げる

1. モバイル幅とデスクトップ幅で手動確認する。
2. 必要ならPlaywrightでスクリーンショット確認を追加する。
3. サウンド通知を実ブラウザで確認する。

## 次に着手する具体タスク

最初に着手するなら、Feature 3、4、5、15 のUI文言整理から行う。

1. `render` のボタン文言を状態ごとに分ける。
2. タイトル文字列生成関数を追加する。
3. `paused` 中のタイトル表示テストを追加する。
4. `npm test` を通す。
5. ブラウザで開始、一時停止、再開、リセットを確認する。

このタスクは影響範囲が小さく、現状の実装と仕様のズレをすぐ減らせる。
